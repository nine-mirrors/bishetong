## 一、起因

外部审查对本项目给出了一组结论，核心不是代码结构，而是「宣称」与「现实」的落差：

1. 论文附件 `/uploads` 挂在全部鉴权之前，任何人都能直接下载；OSS 还返回公共读 URL，盲审等同公开。
2. 上传只校验后缀，不校验内容，改后缀即可上传任意文件。
3. `server/.env` 在本机保存了 DB / JWT / SMTP / OSS / AI 五套真实密钥。
4. `docs/architecture.md` 写 `projects.topicId` 唯一，`schema.prisma` 中没有该约束。
5. `docs/test-report.md` 写种子数据「5 个账号、3 个课题」，实际为 12 / 8。
6. 仓库 0 commit、无 remote，CI 从未触发，材料却写「CI 已跑通」。

第 6 条与文档口径已在本日一并处理，其余为代码级修复。

## 二、安全修复

### 2.1 论文附件改为鉴权下载

- 删除 `server/src/app.js` 中的 `app.use('/uploads', express.static(UPLOAD_DIR))`。
- 删除 `nginx.conf` 与 `vite.config.js` 中的 `/uploads` 转发。
- 新增下载接口：
  - `GET /api/projects/:id/documents/:docId/download`，走 `assertProjectAccess`。
  - `GET /api/blind-reviews/:id/documents/:docId/download`，校验 `reviewerId === req.user.id`，
    下发文件名替换为 `匿名编号-v版本号.扩展名`，避免泄露学生姓名。
- `server/src/services/storage.service.js` 不再拼接公共读 URL：
  - OSS 模式下 `filePath` 只保存内部引用 `oss:<key>`，本地模式为 `/uploads/<文件名>`。
  - 下载由服务端 `get()` 读取后以 `Content-Disposition: attachment` 转发。
  - 统一带 `X-Content-Type-Options: nosniff`、`Cache-Control: private, no-store`。
- 移除 `OSS_PUBLIC_BASE_URL` 配置项，`.env.example` 注明 Bucket 必须私有读。

### 2.2 上传内容校验

`server/src/config/upload.js` 新增 `assertFileSignature`，按文件头魔数识别：

| 扩展名 | 期望类型 | 魔数 |
| --- | --- | --- |
| .pdf | PDF | `%PDF-` |
| .docx / .xlsx / .pptx / .zip | ZIP | `PK\x03\x04` |
| .doc | OLE | `D0 CF 11 E0 A1 B1 1A E1` |
| .md / .txt | 纯文本 | 不含 NUL 字节 |

内容与扩展名不符返回 400「文件内容与扩展名不符」。新增 `server/test/upload.test.js`（7 个用例）。

### 2.3 接口字段收敛

上传响应与文档列表改为字段白名单，不再返回服务端存储路径；上传响应也不再回传全文。
